# Repository knowledge map

Start with a question, not a new document. Search with
`bun run knowledge search <terms> --json`, inspect synonyms and identifiers, then
follow the pointer to its authoritative owner. No tools are needed to read these
Markdown files. [Setup and maintenance](../docs/reference/knowledge.md) explains
commands and [the generated catalog](_index.md) lists all vault articles.

This is a small reference web, not a Markdown migration or new engineering ledger.
Reference `path` values resolve relative to this directory. Standard Markdown links
are usable on GitHub; `related` wikilinks connect vault-root slugs for upstream
search/backlinks. GitHub does not render the generated wikilink catalog as navigation;
use the table above or each pointer's ordinary link there.

`_index.md` and `_backlinks.json` are generated by upstream knowledge-wiki. Never
hand-edit them. `bun run knowledge index` regenerates; `check` rejects drift and
broken structure/references. Backlinks/orphans cover vault relationships, not every
Markdown file in the repository. Owner docs stay connected through their existing
indexes and the repository-wide local link check.

Pointer dates record review of the route and classification, not revalidation of
all underlying runtime/release claims. Knowledge gaps belong beside the unresolved
claim or in the optional `kb gap` inbox; product questions stay in QUESTIONS and
implementation tasks stay in authorized GitHub work records.
