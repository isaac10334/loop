# Public documentation

These pages serve people evaluating or using Loop. Follow [docs guidance](../AGENTS.md).
Start with the reader's goal and explain the supported path, prerequisites,
commands or API, expected result and relevant limits. Use ordinary technical
language; define Loop-specific terms before relying on them.

Describe what works and mark proposals as proposals. Keep concrete trust,
compatibility, failure and disposal constraints where the reader needs them.
Do not import internal task IDs, audit chronology, gate names or agent workflow
into public explanations. Link a technical owner when useful; do not require
historical evidence or internal plans to understand a working example.

For substantial prose changes, explicitly read [the local writing skill](../../skills/loop-writing/SKILL.md).
Check that a newcomer can follow the final page without seeing the old version.
Preserve commands, code, identifiers and link targets during prose-only edits.
Check affected links and claims; report unexecuted examples as unexecuted.

Content changes and site changes are separate scopes. Follow the agreed ownership;
this guidance does not authorize changing site sources or generated output.
