# Documentation ownership

Read [the index](README.md) before adding a document. Put supported usage in guides,
current terms and limits in references, and proposed obligations in `specs/`.
[Public documentation](public/AGENTS.md) has additional reader-facing rules.
Internal references and dated evidence are not onboarding prerequisites.

Write for the named reader and task. Explain current behavior without requiring
knowledge of the preceding diff. Link the owner of a fact instead of copying its
checklist. Label proposals and unverified claims. Preserve unique compatibility,
authority, failure and acceptance details when consolidating pages; do not rewrite
historical receipts to imply a later run passed.

For substantial prose work, explicitly read [the local writing skill](../skills/loop-writing/SKILL.md).
It needs no installation or global settings; do not assume harness skill discovery.
The [internal writing check](reference/writing-check.md) contains rationale and
sample checks; load it only when reviewing the procedure or a difficult passage.

Set finite acceptance and non-goals for the changed documents. Check affected
relative links and compare claims with their source. Record relevant follow-ups
in the handoff or owning document, not automatically in external tasks or ledgers.
`target/site` is the public generated output; do not edit it as documentation source.
The older ignored `site/docs` tree is not deployed.
