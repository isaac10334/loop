# Loop writing

Read this source file explicitly when routed here by repository instructions.
Catalog registration, installation and automatic nested-instruction loading are
harness-specific; this file does not configure them. No external tools are required.

## One bounded pass

1. Read the whole owned passage and enough of its source to understand the claims.
   Name the reader, their question and the answer in one sentence. If the answer
   is missing, flag that gap; do not invent a finding to improve the prose.
2. Protect facts before editing: names, numbers, code, commands, links, negations,
   rankings, scope, uncertainty, authority and failure/disposal conditions.
   Keep proposals distinct from working behavior. Do not edit quotations or
   historical receipts as prose cleanup.
3. Draft the answer first, then the detail needed to use or understand it. Public
   docs describe the current system without requiring the old version or internal
   task history. Internal handoffs may include checks and follow-ups.
4. Read headings, opening sentences and paragraph endings. Replace vague
   significance, staged reveals, repeated "not X but Y" contrasts, forced lists,
   ornamental labels and summary closers when they add no information. Prefer
   an identifiable subject and an explicit verb. Expand compressed noun stacks
   when that makes the sentence easier to parse.
5. Compare source and rewrite claim by claim. Restore lost qualifications; remove
   invented specifics. Retain useful contrast, precise repeated terminology,
   varied sentence lengths and the author's voice. A word or punctuation mark
   alone is not a defect. Do not turn a precise warning into a slogan or weaker
   assurance. Report contradictions separately instead of silently resolving them.
6. Read the final passage as a newcomer: can they find the answer, understand the
   necessary terms and act without the old draft? Check affected links and say
   which examples or claims were not executed or independently verified.

Stop after the claim check and reader pass. Revisit only a concrete remaining
problem; do not add mandatory reviewers, model calls, style scores or repeated
cleanup rounds. For a small passage, do these steps mentally. Read the
[internal writing check](../../docs/reference/writing-check.md) only for rationale,
source provenance or calibration examples; do not load it for every edit.
