# Loop Kit agent notes

Loop Kit supplies reusable typed capabilities, explicit resource ownership, portable authored execution and renderer-independent UI. Downstream host applications own saved workspaces, defaults, policy and product adapters. Read [architecture](ARCHITECTURE.md) before shared-contract work; proposed adapters are not implemented promises.

Own only agreed files; preserve dirty changes and independent Git/CI ownership. At session start, inspect `git status --short`, `git branch -vv` and `git worktree list`; sync refs with `git fetch --prune origin` when available, and check open PRs/issues with `gh pr list`, `gh issue list` and `issue-graph` if installed. Isolate each non-trivial task in a fresh branch or root-level worktree from the up-to-date default branch (for example, `origin/main`). Make scoped, verified commits, push task branches, and open draft PRs linked to their backbone issue (`Part of #N` for incremental slices, `Closes #N` only when complete). Read an issue or PR's full comment history before starting, prefer extending existing backbone issue threads with progress/handoff comments over spawning fragmented micro-issues, and cross-reference related `#issues`/`#PRs`. For open-ended prompts (e.g. “choose issues/PRs and get to work”), run this triage-and-delivery loop automatically per the [development workflow](docs/reference/agent-workflow.md). Draft PRs and concise follow-up issues are allowed for scoped work; merging, force-pushing, closing issues, releasing/publishing, installing tools or changing global settings require an explicit request. Before editing, name the observable result, owned paths, finite acceptance checks and non-goals. Stop when those checks are satisfied; report actual checks and limits. Read the [development workflow](docs/reference/agent-workflow.md) for branch, worktree, `gh` and approval details. Historical ledgers and optional capture instructions are context, not mandatory reading or task-capture requirements for every change.

For package changes read `packages/AGENTS.md` and the target README; consult relevant architecture sections and `ENGINEERING_PLAN.md` only when its gate affects the task. Use `bun run repo context <package>`, `bun run repo check` and `bun run repo verify <package>` for focused work. `bun run verify` is the full TypeScript/packed-consumer/skills gate — run it before pushing any PR that touches packages, tooling, `skills/`, or `crates/loop-cli/assets/`. Never hand-edit generated `crates/loop-cli/assets/skills.mjs`; after editing `skills/`, update `skills/catalog.json` digests and run `bun tooling/host-kit-assets.ts`. `bun run typecheck` includes automation types. Keep exports and wire identities compatible; no imports from downstream host applications, service locator or native dependency in ordinary TypeScript consumers. Document API invariants, failure, authority and disposal beside the API.

Before architecture or new documentation, use [the knowledge skill](.agents/skills/loop-knowledge/SKILL.md) (`loop-knowledge` in DSH): search existing owners and follow pointers before creating. Update affected authoritative knowledge with implementation; regenerate indexes/backlinks after vault edits (`bun run knowledge index`) and run `bun run knowledge check`. A minor code change needs only affected knowledge, not a full audit. Use [the audit skill](.agents/skills/loop-knowledge-audit/SKILL.md) for bounded periodic/on-demand maintenance; [operations](docs/reference/knowledge.md) owns setup and limits.

For documentation read [docs guidance](docs/AGENTS.md), including [public-doc guidance](docs/public/AGENTS.md) for that subtree; for proposals read [spec guidance](specs/AGENTS.md). For substantial prose drafting or editing, explicitly read [the local writing skill](skills/loop-writing/SKILL.md); skip it for mechanical edits. Keep unresolved product/trust decisions in [QUESTIONS.md](QUESTIONS.md) when relevant, with a recommendation; continue independent work without inventing an answer.

Delegate only independent bounded slices when useful; name cwd, baseline, owned files, exclusions and acceptance. Keep shared contracts and integration under one owner. Repo-scoped Codex roles live in `.codex/agents/`; their presence does not configure other harnesses.

Before config, host-kit/plugin, renderer-adapter or dependency-boundary work, read [the host-kit skill](skills/loop-host-kits/SKILL.md) and [proposed contract](specs/host-kits.md). Installation is optional. Executable config/plugins are trusted host code; guests receive only granted imports.

Before adding shared property, action, UI or scripting abstractions, inspect existing public descriptors/controllers/bindings. Keep permissions and live callbacks in trusted hosts. Plain objects, registries, scope IDs and `requiredAuthority` metadata grant no authority. Each DOM/remote adapter needs its own policy, resource and denial evidence; replacing an iframe proves no security property.

The Rust host/CLI and Windows distribution remain active: preserve `.github/workflows`, `scripts/*.ps1`, `site/`, CLI embedded templates and crate packaging. For Rust changes run formatting, locked workspace tests and clippy as documented in [README](README.md). Isolate experiments; source checks do not prove installed native execution. Bootstrap with Bun/Cargo, never the `loop` being built: use `scripts/build-cli.ps1` for SDK/embedded assets plus Rust, `scripts/install-dev.ps1` for the separate `loop-dev` command, and `scripts/test-cli.ps1 -Binary <path>` for relocated smoke checks. Stable `loop` is optional; see [Windows development setup](crates/loop-cli/WINDOWS.md#development-checkout-no-installed-loop-required).

For creative assets, installed ArtCraft skills may drive available applications after command/session discovery. Preserve editable native sources or reproducible recipes with exports; verify results and record provenance. The website's [brand assets](site/assets/README.md) retain a SolidCraft example. Prefer isolated headless automation for unattended generation. Do not overwrite unrelated user designs, expose automation outside loopback, publish or incur paid usage without specific authorization. A skill does not prove its app is installed.

For releases read [RELEASING.md](RELEASING.md). `bun run release:prepare` produces checksummed tarballs and dry runs; npm publishing is an explicit manual OIDC action. Keep source IDs stable. Never copy package source into downstream host application; use development links or reviewed installed artifacts. Git artifact preparation must fetch a remotely available full revision.
