# Independent HK-09 verification

Owned scripts do not edit shared manifests, locks, policy, runtime source or Station.

- `bun test tooling/rust-boundaries.test.ts`: declared local Cargo graph fixtures. Optional, inactive target, build/dev/proc-macro, alias and workspace-inherited edges count. Feature defaults and strong/weak forwarding are interpreted without asking Cargo for an active target graph. Unknown local owners, source overrides, path escapes, cycles and inward native reachability fail.
- `bun tooling/rust-boundaries.ts [--json]`: current workspace graph. Current desktop CLI → host and optional Windows Tao/Wry are intentional positives. Native-default prohibition applies to library roots, not the explicitly desktop CLI. Normal Wasmtime dependencies remain legal in the existing concrete host; pure plan consumers are portable and cannot reach Wasmtime even through an inactive edge.
- `bun tooling/host-kit-verification/packed-consumer.ts <tarball-directory>`: independently consumes already-produced public tarballs outside the checkout in Bun and Node. No source copies/private imports, builds, publishing or global installs. Verifies custom third-party kit resolution, inert coordinator hooks, plain-data rejection, public provider lifecycle/instance independence and private export denial. Temporary consumer is retained and printed for review. Install scripts are disabled. All local workspace dependencies must already be available as tarballs; this is not a production registry availability claim.

- `bun test tooling/host-kit-verification`: independent conditional-import/hidden-platform-edge, factory-profile and nominal-grant/lifecycle regressions. The Node serializer regression intentionally uses Node, because Bun's inherited-array `toJSON` behavior differed during the audit. A controlled Worker unit verifies disposal-completion identity; it is not engine evidence.
- `bun tooling/host-kit-verification/browser-artifact.ts <browser-artifact-directory> [relocated-directory]`: compare all four emitted static files by SHA-256; reject known checkout/platform/dev-only leaks; bind Component bytes, prepared translation plan and every adapter byte to their pins.
- `bun tooling/host-kit-verification/translation-tamper.ts <browser-artifact-directory>`: use installed public artifacts in actual Chrome to reject missing translation pins, changed plans/adapters and changed Component bytes, then boot/dispose the intact artifact. Uses existing browser tooling only; generates an owned temporary profile and random endpoint.
- `bun tooling/host-kit-verification/relocated-cli.ts <produced-loop.exe> [tarball-directory]`: copy the actual binary outside the checkout, create browser/native and both legacy starters, inspect the embedded catalog, check zero config imports before trust, evaluate public installed modules, detect changed transitive input and reject stored-plan digest tampering. No runtime source is copied.
- `bun tooling/host-kit-verification/crate-artifact.ts <actual.crate> [--check-current <checkout>]`: inspect actual tar contents, close every literal Rust embedded-file reference inside the archive, verify artifact hashes and optionally compare recorded build input hashes with the current checkout. Reports unlisted embedded inputs separately; compilation is a different gate.

The declared-manifest checker does not audit third-party registry implementations, compile Rust or prove target availability. Keep locked Cargo metadata/tree, no-default/all-feature/headless/Windows compilation and release relocation gates. It is intentionally independent of Cargo's feature-selected active graph.

Required artifact gates remain separate: real browser Component execution and same-byte receipts; native window/Wasmtime execution; copied standalone CLI archive with embedded evaluator/catalog/starters and no checkout reads; relocated browser output free of Bun/native inputs and production pairing secrets. Source tests and public tarball resolution cannot replace those gates.
